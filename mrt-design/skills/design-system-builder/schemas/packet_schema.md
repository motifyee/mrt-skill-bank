# Packet Schema

YAML template, field descriptions, types, and constraints for the agent context packet.
This file was extracted from `agent_context_packet.md` for maintainability.

---

## Packet Generation Rules

1. **Self-contained.** Agents cannot read the whole skill. The packet must
   include every value an agent needs.
2. **Raw values, not token references.** Agents need hex colors, pixel sizes,
   and font names — not `var(--accent)`. Token names are included for
   reference, but actual values are always present.
3. **Under ~500 lines.** Keep prose minimal. Numeric values and token
   definitions are the priority. Trim descriptions if the packet grows too
   large.
4. **Generated after synthesis.** The main skill produces this packet at the
   end of Phase 1 (interview + token synthesis), before dispatching agents.
5. **Injected into templates.** The packet replaces the `{{CONTEXT_PACKET}}`
   placeholder in each agent's task template (`schemas/agent_task_templates.md`).
6. **Prefer compact operational packets for generation agents.** Keep the full
   packet for documentation and traceability, but strip non-essential prose from
   A-F delivery prompts.

---

## Packet Structure

The packet has these top-level sections. All are required unless marked optional.

**version** -- Protocol version string. Currently `"1.1"`. Incremented when the packet schema changes incompatibly. Agents check this field and reject packets with unrecognized versions.

| Section         | Purpose                                            |
|-----------------|----------------------------------------------------|
| brand           | Identity, audience, industry, trust level          |
| creative_brief  | Shared 3-5 sentence art direction for every agent  |
| aesthetic       | Origin direction, modifications, mood keywords     |
| colors          | Full palette (raw hex), semantics, temperature, dark mode |
| typography      | Families, scale ratio, all type levels with metrics |
| spacing         | Base unit, full scale, container widths, nav height |
| density_system  | Spacing multiplier, section density, whitespace attitude |
| radii           | Scale values for sm/md/lg/xl/full                  |
| shadows         | Elevation levels                                   |
| motion          | Easing curve, duration tokens                      |
| voice           | Tone profile, example words, casing rules          |
| imagery         | Photography, illustration, and image treatment rules |
| components      | Cross-component character rules and signature propagation |
| surfaces        | Which UI surfaces are needed                       |
| constraints     | Framework, accessibility, devices, performance     |
| global_context  | Shared globalization: reading direction, language, locale, date/number format, cultural context, font loading, icon strategy -- REQUIRED for ALL agents (computed from global_context.reading_direction) |
| substitutions   | Inferred values that need flags                    |
| research_evidence | External findings used for synthesis (optional)  |
| decision_log     | Traceability log with explicit evidence links       |
| signature_anchor | The one immediately recognizable visual idea (single phrase) |
| signature_dna    | 3+ propagation rules -- which components carry the mark and how |
| signature_moment | Legacy field -- concept, placements, constraints, systemic_effects |
| tension_points   | Deliberate scale, density, and structural contrasts |
| intentional_gaps | What was compressed out of packet slices             |
| cultural_context | Region, color associations, date/number formats (optional) |

structured Markdown block. Below is the canonical format using a YAML-like
